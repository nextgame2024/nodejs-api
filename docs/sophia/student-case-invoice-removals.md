# Linked invoice deletion and voiding

Source: [Xero Accounting API invoices](https://developer.xero.com/documentation/api/accounting/invoices), checked 31 October 2026. DRAFT and SUBMITTED invoices can transition to DELETED. AUTHORISED invoices without payments or credit allocations can transition to VOIDED. Invoices do not have an archive transition. PAID, DELETED, VOIDED, partially settled, or unknown-status invoices have no removal action. Provider lock periods and other provider restrictions are enforced by the provider at update time.

The linked-invoices endpoint calculates `removalAction` from cached status and balances for users with `cases.manage`, `payments.prepare`, and `payments.read_all`. The new Action column shows a trash icon only when that action is available. The confirmation explicitly says Delete or Void. No internal application names appear in confirmation or success messages.

`POST /api/business-packs/student-operations/v1/workspace/cases/:caseId/invoices/:connectionId/:invoiceId/remove` takes `{action:"delete"|"void"}` plus an Idempotency-Key. The server authorizes the case, verifies the exact linked connection/invoice and contact, claims a short durable lease, and reads the current invoice before issuing a status-only POST. Paid or credited invoices are rejected, and cached balances are refreshed to hide an obsolete action. It never removes payments or credits.

The durable removal row and deterministic provider key allow retries after network timeouts or local transaction failures. A retry first checks whether the exact final status already exists. The local finalization updates the invoice cache and creation receipt, stops stale receipt recovery, records activity, reconciles the checklist, and marks removal completed. Active linked-invoice rows and counts exclude completed removals while retaining original links and audit history. No provider calls occur while holding the database transaction open.
