# Xero capability matrix for Payment Operations

Research checkpoint, 27 November 2026. This matrix describes the public contracts. The customer's actual grants, Xero user privileges, enabled accounts, app subscriptions and Stripe arrangement need separate validation. See the [solution design](payment-operations-design.md) and [delivery and test plan](payment-operations-delivery.md).

Accounting routes below are relative to `https://api.xero.com/api.xro/2.0`. Each request carries the connection's server-resolved `Xero-tenant-id` and bearer token. In the method column, scope names starting with a dot are prefixed by `accounting`. A write grant covers the corresponding read. Use granular scopes from the current consent guide, including where the published SDK specification still shows the legacy transaction scope. Request new grants from Company integrations only when a feature needs them. [Scope-to-resource mapping](https://developer.xero.com/documentation/guides/oauth2/scopes/) · [Xero Accounting OpenAPI contract](https://github.com/XeroAPI/Xero-OpenAPI/blob/master/xero_accounting.yaml)

| Capability | Xero API Support | Endpoint / Method | Limitations | Proposed Sophia AI Approach |
|---|---|---|---|---|
| Connect two organisations | Fully supported | OAuth code flow, `GET https://api.xero.com/connections`, `GET /Organisation`, `GET /Accounts`. Use `offline_access` for refresh and `.settings.read` for organisation/accounts. | A grant can cover multiple connections. Each accounting call has one target. Roles, accounts, IDs and granted access vary by organisation. | Require explicit TRUST and operating assignments, store the external tenant ID with each object and verify the target before every command. [OAuth tenants](https://developer.xero.com/documentation/guides/oauth2/tenants/) |
| Read student, college, invoice and bill information | Fully supported | `GET /Contacts/{id}` with `.contacts.read`. `GET /Invoices`, `GET /Invoices/{id}` with `.invoices.read`. | ACCREC and ACCPAY have different directions. Fetch detail for line IDs, credit applications and payments when list summaries omit them. A paid invoice can include credits. | Reuse the register. Compare amount due, paid and credited separately. Import only relevant bills for the new obligation view. [Invoices](https://developer.xero.com/documentation/api/accounting/invoices/) · [Contacts](https://developer.xero.com/documentation/api/accounting/contacts/) |
| Create a student invoice, college bill or commission invoice | Fully supported | `PUT /Invoices` create, `POST /Invoices/{id}` update eligible document with `.invoices`. | The invoice type, contact, tax, dates, status and accounts belong to the target organisation. Locks, payments and credits constrain edits. A draft requires authorisation before applying a payment. | Keep existing draft exports. Add a college bill only under an approved payable policy. A bank receipt does not authorise an invoice. [Invoices](https://developer.xero.com/documentation/api/accounting/invoices/) |
| Register and read an invoice payment | Fully supported | `GET /Payments[/{id}]` with `.payments.read`, `PUT /Payments` with `.payments`. | One document per payment, approved AR/AP, positive amount up to remaining due, BANK or payments-enabled account. Invoice currency, account currency and rate have distinct meanings. | Use for an approved verified TRUST receipt, actual payment of a college bill or actual PTY collection. Return PaymentID and refresh the invoice. Pre-feed posting is possible. [Payments](https://developer.xero.com/documentation/api/accounting/payments/) |
| Allocate a partial payment to named tuition/materials lines | Partially supported | Same `PUT /Payments` for invoice amount, `GET /Invoices/{id}` for lines. Scopes above. **No payment-to-LineItemID write.** | The payment references the document. Xero's credit allocation endpoints also target invoices. | Store intended coverage against versioned line IDs locally, including an unassigned remainder. Xero owns the invoice balance. [Payments](https://developer.xero.com/documentation/api/accounting/payments/) |
| One deposit covers several invoices | Partially supported | `GET /BatchPayments[/{id}]`, `PUT /BatchPayments` with `.payments.read` or `.payments` respectively. | Batch receipts and bill payments are accounting objects. Eligibility depends on invoice types, currencies and account. Each member must be payable. | MVP proposes explicit splits and operator handoff. Enable suitable same-organisation batches only after an AUD batch-deposit contract test. Retain batch and component PaymentIDs. [Batch payments](https://developer.xero.com/documentation/api/accounting/batchpayments/) |
| Correct a posted payment | Partially supported | `POST /Payments/{id}` with status `DELETED`, `.payments`. | No edit-in-place. Batch/receipt-origin payments excluded from this individual reversal. Locks and reconciliation can require action in Xero. Deleting an accounting payment does not send a refund. | Record a correction case, gather approval, reverse only eligible objects and authorise replacement separately. Read back both outcomes. [Payments](https://developer.xero.com/documentation/api/accounting/payments/) |
| Read/create spend or receive money | Fully supported | `GET /BankTransactions[/{id}]` with `.banktransactions.read`, `PUT /BankTransactions` create, `POST /BankTransactions/{id}` for eligible updates with `.banktransactions`. | Excludes invoice payments, bank transfers and raw bank-feed lines. Spend/receive objects expose `IsReconciled`. Editing pre/overpayment bank transactions is restricted. | Show recorded transactions by type. Prevent a second receive-money posting against funds already applied to an invoice. [Bank transactions](https://developer.xero.com/documentation/api/accounting/banktransactions/) |
| List raw unreconciled Xero statement lines, preview Xero's suggested match, approve/match a line | Unsupported | No public Accounting endpoint, method or OAuth scope. | Xero explicitly declines exposing this data or letting apps perform bank-statement reconciliation. | Collect independently authorised evidence or an uploaded statement. Prepare suggestions locally. Staff finish Find & Match in the correct Xero organisation. [Xero platform decision](https://xero.uservoice.com/forums/5528-xero-api/suggestions/2884040-reconcile-via-the-api) · [Xero reconciliation workflow](https://central.xero.com/0/article/Reconcile-your-bank-account) |
| Observe reconciliation for a known object | Partially supported | `GET /Payments/{id}`, `/BankTransactions/{id}`, `/BatchPayments/{id}`, `/BankTransfers/{id}` with the corresponding payment/bank transaction read grants. | Object-level flags, including separate transfer legs. Flags do not identify the statement line. The documented payment write flag has a conversion use case. No guarantee of a webhook on reconciliation alone. | Omit `IsReconciled` on writes. Refresh known IDs, store flag, source and time. Missing/unavailable is unknown. Preserve staff attestation separately. [Payments](https://developer.xero.com/documentation/api/accounting/payments/) · [Transfers](https://developer.xero.com/documentation/api/accounting/banktransfers/) |
| Specialised statement access | Requires additional verification or access | Finance `GET /BankStatementsPlus/statements`, `finance.bankstatementsplus.read`. Partner Bank Feeds `GET/POST /bankfeeds.xro/1.0/Statements`, new partners use `bankfeedsv2`. | Finance access is purpose/licence restricted. Bank Feeds lets financial institutions deliver statements and inspect submissions. The Advanced-tier Account Data beta exposes accounting activity. None confers general reconciliation access. | Exclude these as MVP dependencies. Separately assess customer-authorised bank/provider consent, account coverage, identifiers and retention before integrating a bank. [Finance specification](https://github.com/XeroAPI/Xero-OpenAPI/blob/master/xero-finance.yaml) · [Bank Feeds](https://developer.xero.com/documentation/api/bankfeeds/statements) · [Account Data](https://developer.xero.com/documentation/api/accountdata/overview) |
| Identify and record an excess | Partially supported | `GET /Overpayments[/{id}]` with `.payments.read`, create via `PUT /BankTransactions` of type `RECEIVE-OVERPAYMENT` or `SPEND-OVERPAYMENT` with `.banktransactions`. | Separate document, single overpayment line. No general overpayment-create call on /Overpayments. Carry the returned OverpaymentID and originating BankTransactionID when available. | Detect locally before posting. Agree one method per event, e.g. pay amount due plus a separate excess. Reconcile the one deposit to the selected records in Xero. [Overpayments](https://developer.xero.com/documentation/api/accounting/overpayments/) · [Bank transactions](https://developer.xero.com/documentation/api/accounting/banktransactions/) |
| Record a genuine advance before invoicing | Fully supported | `GET /Prepayments[/{id}]` with `.payments.read`, `PUT /BankTransactions` with `RECEIVE-PREPAYMENT` or `SPEND-PREPAYMENT`, `.banktransactions`. | Creation limited to organisation base currency. An advance needs an identified purpose and approved account/tax treatment. | Use only for a confirmed advance under policy. Unknown payer remains in investigation. [Prepayments](https://developer.xero.com/documentation/api/accounting/prepayments/) · [Bank transactions](https://developer.xero.com/documentation/api/accounting/banktransactions/) |
| Issue a commercial credit | Fully supported | `GET /CreditNotes[/{id}]` with `.invoices.read`, `PUT /CreditNotes` create, `POST /CreditNotes/{id}` for eligible updates with `.invoices`. | Sales or purchase credit changes the underlying accounting obligation. Creating one for a cash surplus could reduce revenue incorrectly. | Use for approved variations, cancellations or billing corrections, with reason and links to the original document. [Credit notes](https://developer.xero.com/documentation/api/accounting/creditnotes/) |
| Apply or remove an existing credit allocation | Fully supported | `PUT /{Overpayments,Prepayments,CreditNotes}/{id}/Allocations`. `DELETE` same path plus `/{AllocationID}`. Read allocations on parent detail. Over/pre: `.payments`. Credit notes: `.invoices`. | Match contact, organisation, currency eligibility and AR/AP direction. Cap at remaining credit and invoice due. Respect dates/status/locks. | Introduce reserve, approve, post, read-back and immutable reversal history. Recheck both balances immediately before write. [OpenAPI](https://github.com/XeroAPI/Xero-OpenAPI/blob/master/xero_accounting.yaml) · [Xero contact-matching change](https://developer.xero.com/changelog) |
| Record a refund of credit | Fully supported | `PUT /Payments` with one of OverpaymentID, PrepaymentID or CreditNoteID and eligible account, `.payments`. | Records money returned. Xero accounting registration does not instruct a bank or Stripe to move funds. A reversal of the original invoice payment has different effects. | Require refund evidence, verified destination, remaining credit and independent approval. Link actual refund and accounting receipt. [Payments](https://developer.xero.com/documentation/api/accounting/payments/) |
| Same-organisation transfer | Fully supported | `GET /BankTransfers[/{id}]` with `.banktransactions.read`, `PUT /BankTransfers` create, `POST /BankTransfers/{id}` delete eligible transfer with `.banktransactions`. | Both accounts must exist in the same organisation. Accounting entry only. The two legs can reconcile separately. | Candidate for an actual Stripe clearing-to-bank movement if both are suitable bank accounts and no integration already books it. [Bank transfers](https://developer.xero.com/documentation/api/accounting/banktransfers/) |
| TRUST→PTY transfer, direct-college receipt, or initiate an EFT through Accounting | Unsupported | No cross-tenant transfer or general bank-disbursement endpoint. No TRUST bank payment is applicable for a student-to-college movement. | Independent legal books and actual bank instructions. | Capture evidence, use optional independent tenant-specific accounting commands only under accountant-approved policy. [Bank transfers](https://developer.xero.com/documentation/api/accounting/banktransfers/) |
| Store evidence on accounting records | Partially supported | `GET /{resource}/{id}/Attachments`, `GET/PUT/POST .../Attachments/{filename}` with `.attachments.read` / `.attachments`. Existing optional Files API uses `files` for file/association writes. | Only supported parent resources, e.g. Invoice, CreditNote, BankTransaction, Contact or BankTransfer. No generic Payment attachment path. Invoices document up to 10 files, 25 MB each. Online visibility is a separate option. | Keep private evidence with a case link. On approval, attach to a suitable same-tenant parent, record returned ID and checksum, default to private. Respect any tighter local limit. [Attachments](https://developer.xero.com/documentation/api/accounting/attachments/) · [Invoice limits](https://developer.xero.com/documentation/api/accounting/invoices/) · [Files](https://developer.xero.com/documentation/api/files/overview/) |
| Annotate an accounting action | Fully supported | For payments, `GET/PUT /Payments/{id}/History` with `.payments.read` / `.payments`. Use history only on documented resource types. | Free-text notes are visible in that organisation. They cannot prove delivery or bank settlement. | Optionally add a brief case/communication reference after approval. Preserve the full event trail in Sophia. [Payments history](https://developer.xero.com/documentation/api/accounting/payments/) |
| Notify invoice contact | Partially supported | `POST /Invoices/{id}/Email` empty body, `.invoices`. | Eligible ACCREC statuses SUBMITTED, AUTHORISED or PAID. Contact and included contact persons, organisation template, sender tied to authorising user. Limits by organisation, demo cannot send. HTTP 204 is request success. | Reserve for deliberate invoice notification. The action cannot specify arbitrary recipients, subject, body or an ad hoc attachment set. [Invoice email](https://developer.xero.com/documentation/api/accounting/invoices/) |
| Send college remittance, cover letter and custom evidence, track delivery | Unsupported | No general-purpose Accounting email, payment-confirmation mail or delivery-history endpoint for this workflow. | History and document flags do not establish delivery, receipt by college or settlement. | Preview and approve in Sophia, send via existing mail infrastructure, retain provider message ID and independently evidenced delivery status. [Invoice email contract](https://developer.xero.com/documentation/api/accounting/invoices/) |
| Receive change notifications | Partially supported | App-configured HTTPS webhook POST, signed raw body. No webhook OAuth scope. Use resource read grants to hydrate, offline access to stay connected. | Contact/invoice and credit note, overpayment, prepayment and payment creation/update categories documented. PAYMENT CREATE/UPDATE covers creation/deletion semantics. Verify categories and envelope versions enabled for this app. No documented general bank transaction, bank line, payout or reconcile-complete event. | Add category-aware parsing to the current INVOICE/CONTACT listener. Persist and deduplicate before acknowledgement, then fetch by tenant and ID. Keep polling. [Webhook overview](https://developer.xero.com/documentation/guides/webhooks/overview) · [Payment payload](https://developer.xero.com/documentation/guides/webhooks/payments) · [5 November release](https://developer.xero.com/changelog) |
| Check totals and aged balances | Partially supported | `GET /Reports/AgedReceivablesByContact` and `AgedPayablesByContact` with contactID and `.reports.aged.read`. `GET /Reports/BankSummary` with `.reports.banksummary.read`. | Report permissions and as-of dates matter. Aggregates cannot identify missing feed lines or prove a specific match. | Optional per-organisation control totals and discrepancy investigation. Show coverage/date and restrict export. [Reports](https://developer.xero.com/documentation/api/accounting/reports/) |
| Handoff to a specific Xero document | Fully supported | Use ShortCode from `GET /Organisation` with `.settings.read` and documented payment/invoice/bank-transaction deep links. | Link opens the user's Xero session with its own permissions. No documented deep link to an arbitrary unreconciled line. | Hand off with account, date, reference, amount and expected document IDs. Fall back to the named organisation/account and Find & Match. [Deep links](https://developer.xero.com/documentation/guides/how-to-guides/deep-link-xero/) |
| Identify Stripe gross/fees, balance availability and payout membership | Requires additional verification or access | Accounting reads may show invoice payments, bank transactions and transfers with scopes above. Stripe read access: `GET /v1/payment_intents/{id}`, `/v1/charges/{id}`, `/v1/balance_transactions`, `/v1/payouts[/{id}]`. | Xero may already book receipts/fees. It does not promise processor-level payout membership or availability dates. Automatic payouts support the payout filter. Manual and instant payouts lack provider-assigned transaction membership. | Inventory client feed/payment service, sales channels, merchant account and sample exports. Consume existing postings, supplement with read-only Stripe or approved CSV. Preserve provenance of manual allocations. [Xero Stripe payments](https://central.xero.com/0/article/Connect-Stripe-Bank-transfer-to-Xero) · [Stripe payout reconciliation](https://docs.stripe.com/payouts/reconciliation) · [Instant payout limitation](https://docs.stripe.com/reports/payout-reconciliation) |

**Release evidence.** Validate endpoint scope grants, invoice and batch eligibility, actual webhook envelopes, reconciling in the UI followed by API reads, and external attachment visibility in two disposable tenants. API access, accounting policy and authorisation to pay are three separate review decisions.
